# TianCode 业务功能入口实施方案

[English](FEATURE_ENTRIES_PLAN.md) | 中文

范围：聊天输入框上方的业务快捷栏、可用 Skill 发现、公职办公工作流、编报模板与 dev 环境验证。

快捷栏放在输入卡片上方。点击“编报生成”即选择该功能并向上展开模板菜单，选中模板后更新草稿并关闭菜单；选中功能后不显示说明文字。浏览器验证覆盖位置、模板替换、菜单关闭、双主题与窄窗口。

1. 在 Conversation 输入卡片上方声明业务入口插槽，由 Skill UI 提供快捷栏；复用现有图标、菜单、主题变量和中英文词典。
2. 入口从当前会话可调用的 Skill 目录取得，配置控制常用入口及排序，其余进入“更多”。选中入口将可见的 `/skill` 加入当前草稿；切换保留需求正文和附件，普通对话移除业务前缀，发送继续使用现有后端 Skill 加载与会话日志。
3. 在 Office 资源包中提供可选的公职办公技能：汇报 PPT、编报生成、公文写作、会议纪要、工作总结、方案预案、讲话材料、材料校核、台账分析。桌面应用启用该资源组，Web dev 通过 overlay 启用。
4. 编报吸收山海鉴的事件综述、专题研判、阶段复盘、素材核对模板，以及模板版本、大纲确认、分节草稿、小结修订、汇总和来源核对流程；资料读取使用当前工作区，交付 Markdown／DOCX。PPT 使用现有 Office 环境交付可编辑 PPTX。
5. 覆盖草稿切换、可用目录、配置拒绝、真实 Loader 资源加载、技能注入的会话记录、组件操作与浏览器布局测试。检查主题、窄窗口、菜单键盘与关闭行为、发送失败和会话切换。
6. 启动 TianCode dev，检查快捷栏和模板选择的实际效果；更新使用说明与状态，记录实际执行的验证及环境限制。

## 开发预览

在仓库根目录运行 `pnpm run build:tiancode`，再运行 `DSH_DESKTOP_OPEN_DEVTOOLS=0 pnpm run start:desktop`。当前开发窗口提供办公快捷栏；点击“编报生成”后在按钮上方展开四种模板。发送前添加工作区材料与任务要求。

## 验证记录

- 快捷栏布局验证：Skill UI、输入框控件与焦点样式共 156 项定向测试通过，包含欢迎页和已有对话的位置，以及模板切换时草稿的同步更新。
- 构建产物浏览器交互：1 项测试通过，覆盖快捷栏位于卡片上方、模板菜单向上展开、正文保留、模板切换、双主题、窄窗口尺寸与菜单关闭。
- Headless `public-report` 会话回放：选中的 1 个场景通过，包含技能注入的持久记录和独立检查的输出文件；夹具采用合成材料与预编写模型响应。
- `build:tiancode`、Host/Client TypeScript 检查与 lint 通过；受影响 README 和方案的定向双语配对通过；`doc-sync` 中的客户端、配置和工具目录新鲜度检查通过。
- 完整 `doc-sync`：40 项门禁通过，3 项因已有文档的双语配对、换行与仓库引用问题失败。`uv run pytest` 缺少 Python SDK/runtime 包而无法收集测试；`uv run ruff .` 因未安装 Ruff 而无法启动。
- 实际模型生成质量及单位报送格式仍需使用部署配置的模型和批准材料验收。
